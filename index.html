01
PRIMEIRO, O ESSENCIAL

O que é WebSocket, exatamente?

↔
DEFINIÇÃO

WebSocket é um protocolo de comunicação que mantém uma conexão aberta entre cliente e servidor e permite que os dois lados enviem dados a qualquer momento pela mesma conexão.

🔌

1 conexão persistente

Depois do handshake, cliente e servidor continuam conectados. Não é necessário abrir uma nova requisição HTTP para cada mensagem.

↔

Full-duplex

Cliente e servidor podem transmitir simultaneamente. O servidor não precisa esperar o cliente perguntar se existe uma atualização.

📦

Mensagens em frames

Depois do upgrade, os dados deixam de ser trocados como requisições HTTP e passam a viajar em frames WebSocket.

⚡

Baixa sobrecarga

O cabeçalho de cada frame costuma ser pequeno em comparação com repetir cabeçalhos HTTP completos em cada atualização.

✕ NÃO É

“Uma requisição HTTP que fica carregando para sempre.”

→
✓ É

Um protocolo próprio que normalmente começa com um handshake HTTP e depois muda para frames WebSocket.

PILHA SIMPLIFICADA

Onde ele fica na comunicação?

Aplicação Chat • Dashboard • Jogo • Colaboração
WebSocket Frames • Mensagens • Ping/Pong • Close
TLS (quando wss://) Criptografia e proteção em trânsito
TCP Canal confiável e ordenado de bytes
IP / Rede Entrega dos pacotes pela rede

ws:// usa WebSocket sem TLS. wss:// usa WebSocket protegido por TLS — o equivalente seguro e recomendado em produção.

Sec-WebSocket-Key

Nonce aleatório enviado pelo cliente. O servidor combina esse valor com um GUID definido pelo protocolo, calcula SHA-1 e retorna o resultado em Base64.

101 Switching Protocols

Confirma o upgrade no handshake HTTP/1.1. A partir daí, aquela conexão passa a carregar frames WebSocket.

Sec-WebSocket-Version: 13

Indica a versão padronizada pelo RFC 6455. A versão 13 é a versão usada pelo protocolo WebSocket padronizado.

Detalhe técnico

WebSocket também pode ser inicializado sobre HTTP/2 usando Extended CONNECT (RFC 8441). O fluxo acima mostra o handshake clássico HTTP/1.1 do RFC 6455, que é o melhor ponto de partida para entender o protocolo.

O detalhe que muda tudo

Depois que a conexão está em OPEN, o servidor pode enviar uma mensagem sem receber uma nova requisição do cliente. É isso que diferencia WebSocket de um fluxo tradicional de request/response HTTP.

04
POR BAIXO DO CAPÔ

Como um frame WebSocket é montado?

Uma mensagem pode ocupar um ou vários frames. O cabeçalho indica como interpretar o payload.

CAMPO SELECIONADO

FIN

Quando vale 1, este é o último frame da mensagem. Uma mensagem fragmentada pode usar vários frames.

Cliente → servidor MASK = 1 obrigatório

Frames enviados por clientes precisam ser mascarados com uma chave aleatória de 32 bits.

Servidor → cliente MASK = 0 obrigatório

O servidor não mascara os frames enviados ao cliente.

Frames de controle ≤ 125 bytes

Close, Ping e Pong não podem ser fragmentados e têm payload máximo de 125 bytes.

0x0Continuation
0x1Text
0x2Binary
0x8Close
0x9Ping
0xAPong

ESCOLHA A FERRAMENTA CERTA

WebSocket vs Polling vs SSE

“Tempo real” pode ser implementado de formas diferentes. WebSocket não é a resposta para tudo.

Cliente
Servidor
COMUNICAÇÃO Bidirecional
CONEXÃO Persistente
MELHOR PARA Interação em tempo real nos dois sentidos

Uma única conexão permanece ativa e os dois lados enviam mensagens quando necessário.

USE WEBSOCKET QUANDO

Existe conversa contínua nos dois sentidos

  • Chats e mensageria instantânea
  • Jogos multiplayer
  • Dashboards operacionais em tempo real
  • Colaboração simultânea
  • Notificações + comandos interativos
TALVEZ NÃO PRECISE

O fluxo é simples ou esporádico

  • CRUD tradicional e APIs REST
  • Páginas que atualizam raramente
  • Somente servidor → cliente: SSE pode bastar
  • Processos que não exigem baixa latência
  • Infraestrutura que não precisa manter conexões longas

Ciclo de vida de uma conexão

0
WebSocket.CONNECTING

A conexão ainda está sendo estabelecida.

O construtor foi chamado, mas o handshake ainda não terminou. Ainda não é possível enviar mensagens.

KEEPALIVE / SAÚDE DA CONEXÃO

Ping ↔ Pong

Endpoint A
PING PONG
Endpoint B

Ping e Pong são frames de controle do protocolo. Na API nativa WebSocket do navegador, esses frames não são expostos diretamente ao JavaScript; o navegador cuida do comportamento protocolar.

07
DO CONCEITO AO CÓDIGO

Como fica no JavaScript?

client.js 
const socket = new WebSocket("wss://exemplo.com/ws");

socket.addEventListener("open", () => {
  console.log("Conectado!");
  socket.send("Olá, servidor!");
});

socket.addEventListener("message", (event) => {
  console.log("Recebido:", event.data);
});

socket.addEventListener("close", (event) => {
  console.log("Fechou:", event.code);
});

socket.addEventListener("error", (error) => {
  console.error("Erro no WebSocket", error);
});
1
new WebSocket(url)

Inicia o handshake e cria o objeto da conexão.

2
open

Dispara quando a conexão chega ao estado OPEN.

3
send()

Envia texto, Blob, ArrayBuffer ou ArrayBufferView.

4
message

Entrega ao cliente uma mensagem recebida do servidor.

5
close()

Inicia o encerramento da conexão usando um frame Close.

⚠
Reconexão não é automática

A API nativa do navegador não reconecta sozinha. A aplicação precisa implementar retry/backoff quando isso for desejado.

🧠
TCP confiável ≠ “mensagem garantida para sempre”

TCP ordena e retransmite enquanto a conexão existe, mas a aplicação ainda precisa tratar quedas, retomada e consistência.

08
PRODUÇÃO DE VERDADE

Segurança e boas práticas

🔒

Use wss://

Proteja credenciais e mensagens com TLS. Em produção, WebSocket sem criptografia raramente é apropriado.

🪪

Autentique e autorize

Validar quem abriu o socket não basta: confira também se aquele usuário pode executar cada ação recebida.

🌐

Valide Origin

Ajuda a reduzir riscos de Cross-Site WebSocket Hijacking quando autenticação baseada em cookies está envolvida.

📏

Limite payload e frequência

Defina tamanho máximo, rate limiting, timeout e proteção contra clientes que mantêm conexões abusivas.

✅

Valide cada mensagem

Trate conteúdo recebido como entrada não confiável. Valide schema, tipo, tamanho e regras de negócio.

📊

Observe a conexão

Monitore conexões ativas, latência, erros, fechamentos, filas de saída e consumo de memória.
